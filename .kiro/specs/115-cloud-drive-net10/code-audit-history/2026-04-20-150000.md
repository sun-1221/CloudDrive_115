## 问题清单

### ❌ H1 [新] HTTP 超时默认值 30s ≠ 需求规定 10s

- **优先级**: High
- **需求**: R9.2、R9.3
- **位置**: `Server/src/Infrastructure/Http/HttpClientSetup.cs:23`
- **权威**: requirements.md:139–140 "超时策略（默认 10 秒，可通过配置调整）"
- **现状**: `DefaultTimeout = TimeSpan.FromSeconds(30)`
- **期望**: `DefaultTimeout = TimeSpan.FromSeconds(10)`
- **影响**: 读/写请求超时阈值偏离需求 3 倍，外部 API 调用响应缓慢时不会按预期 10s 中断
- **修复**: 将 `HttpClientSetup.cs:23` 的 `TimeSpan.FromSeconds(30)` 改为 `TimeSpan.FromSeconds(10)`

### ⚠️ M1 [新] Program.cs 未调用 SqlSugar InitTables()

- **优先级**: Medium
- **需求**: R5.4
- **位置**: `Server/src/WebApi/Program.cs`（缺失调用）
- **权威**: requirements.md:91 "应用启动时…SHALL 调用 `db.CodeFirst.InitTables<T>()`"
- **现状**: `SqlSugarSetup.InitTables()` 静态方法已提供，但 Program.cs 无调用
- **说明**: 因框架 spec 无业务实体，调用延迟至业务模块合理；tasks.md:114 描述为"提供应用启动时…的调用入口"
- **建议**: 不阻塞。业务模块（115-cloud-drive-integration）集成时应在 Program.cs 添加调用

### ⚠️ M2 [新] WebApi.csproj 直接引用 SqlSugarCore 包

- **优先级**: Medium
- **需求**: 架构规则（WebApi 不应直接依赖 ORM 包）
- **位置**: `Server/src/WebApi/WebApi.csproj:19`、`Program.cs:9` (`using SqlSugar;`)
- **原因**: Program.cs 直接使用 `SqlSugar.DbType` 枚举配置数据库类型
- **影响**: WebApi 层直接引用 ORM 包，违反最小依赖原则
- **建议**: 将 DbType 解析封装进 `SqlSugarSetup.AddSqlSugar()` 的重载方法（如接受 `string dbType` 参数），消除 WebApi 层对 SqlSugarCore 的直接包引用

### ⚠️ M3 [新] Domain 层存在 4 个孤儿文件

- **优先级**: Medium
- **需求**: 反向追溯 — 代码无法映射到 net10 spec 的任何需求
- **文件**:
  - `Server/src/Domain/Enums/CloudDriveJobStatus.cs`
  - `Server/src/Domain/Enums/CloudDriveJobType.cs`
  - `Server/src/Domain/Enums/CookieSessionStatus.cs`
  - `Server/src/Domain/ValueObjects/CookieTriplet.cs`
- **说明**: 这些是 `115-cloud-drive-integration` spec 的业务域类型，混入了框架 spec 的实现范围
- **建议**: 确认归属。若属于 integration spec，应在该 spec 的 tasks 中追溯；若属于框架 spec 预留类型，应在 requirements/design 中体现
