## 遗留问题详情

### N1. [遗留] Property 1-11 节未使用规范的 `_覆盖需求:_` 格式

- **位置**：`design.md:339, 345, 351, 357, 363, 369, 375, 381, 387, 393, 399`
- **当前状态**：未修复。仍为 `**Validates: Requirement(s) X.X**`。
- **权威依据**：`spec-format.md:106` 要求每个核心组件必须标注 `_覆盖需求: X.X, Y.Y_`；`quality-dimensions.md:47` 要求每个设计组件有需求来源。
- **差异说明**：规范要求可机读的 `_覆盖需求:_` 字段；当前 `**Validates:**` 是自然语言陈述。Property 1-11 已被 `tasks.md` 的属性测试任务作为 `_设计: §Property N..._` 引用，应视为设计组件。
- **影响**：不阻塞实现，但会降低后续自动化追溯、覆盖矩阵抽取和跨 spec 复用的一致性。
- **建议修复**：保留 `**Validates:**` 的同时追加 `_覆盖需求: ..._`，或整体替换为 `_覆盖需求: ..._`。

### N2. [遗留] `.config.kiro` 字段名不符合 `spec-format.md`

- **位置**：`.config.kiro:1-5`
- **当前状态**：未修复。当前内容仍为：

```json
{
  "specName": "115-cloud-drive-net10",
  "description": ".NET 10 原生框架搭建（替代 ABP）",
  "version": "1.0.0"
}
```

- **权威依据**：`spec-format.md:24-28` 规定 `.config.kiro` 格式为：

```json
{"specId": "<uuid>", "workflowType": "requirements-first|design-first", "specType": "feature|bugfix"}
```

- **差异说明**：规范字段为 `specId/workflowType/specType`；当前字段为 `specName/description/version`，字段集合不相交。
- **影响**：若工具链依赖 `specId`、`workflowType` 或 `specType`，将无法解析该 spec 的标准元数据。
- **建议修复**：至少补齐规范字段；若保留现有扩展字段，应先在 `spec-format.md` 中约定扩展字段。

### N3. [遗留] `design.md §1. SqlSugar 配置与仓储` 缺少 `IDomainEventSource.Track` 调用描述

- **位置**：`design.md:232-241`
- **当前状态**：未修复。§1 仍只列出 Scoped 注册、连接管理、自动建表、仓储基类与复杂查询边界，未说明 Repository Insert/Update 后追踪聚合。
- **上游需求**：`requirements.md:94`（R5.7）要求 Repository 执行 Insert/Update 等持久化操作后调用 `IDomainEventSource.Track(entity)` 或等效方法。
- **现有兜底**：

  - `tasks.md:113` 在 T5.1 中明确写入 Repository 持久化成功后调用 Track。
