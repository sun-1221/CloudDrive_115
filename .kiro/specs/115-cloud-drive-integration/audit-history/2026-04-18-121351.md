## 新发现问题的历史反思

本轮为**首次审核**，所有问题均为 `[新]` 标记。为避免下次审核遗漏：

1. **错误字段大小写与类型需逐端点核对**：采集文档已明示字段名（`errCode` / `errNo` / `errno`）和类型（`string` vs `number`），但我在初始写 requirements.md 时将其简化归类到 6 种变体表，**未按端点独立核对**。下轮应对所有错误字段按 URL 路径逐行核对。
2. **URL 参数完整性容易被忽略**：`aid=1`、`ct=lixian`、`format=json`、`share_id=0` 等官方 URL 中出现但"看似默认值"的参数，实际可能是必填。下轮应机械地将官方 URL 拆分为 `path + query` 后逐参数核对。
3. **敏感字段黑名单应从官方响应 schema 反向生成**：我写 spec 时列的是"常见个人信息字段"，但官方 `proapi/3.0/index.php` 实际返回 20+ 字段，应反向扫描 schema 中所有 `string` 类型字段并判断语义。
4. **幻影需求往往来自"开放平台文档 → 网页端 API"的未过滤沿用**：如 `gte_day/lte_day` 来自开放平台，网页端实际是 `date`。下轮审核应严格要求"每个参数 → 官方采集 URL 中的参数"一一对应。
