## 新发现问题

### H-01 `/rb` 回收站响应字段与 docs 不对齐

- **优先级**：🔴 高
- **状态**：`[新]`
- **specs 位置**：
  - `requirements.md:277`：声明 `id/file_name/type/file_size/dtime/thumb_url/cid/parent_name/pick_code/status` 等 item 字段
  - `design.md:1034`：`RecycleBinItemId` 注释写明用于 `webapi.115.com/rb/*` 还原/彻底删除的 `tid` 参数
  - `tasks.md:313`：同样要求补 `RecycleBinItemId`、`RestoreStatus` 与 `tid` 语义
- **官方依据**：`docs/115-api-docs.md:535-565` 的 `/rb` 采集 schema 仅包含 `count/rb_pass/state/error/offset/page_size/order/is_asc`，未采集到回收站 item 数组，也未采集 `id/file_name/type/status/tid`
- **差异说明**：官方文档当前不足以支撑回收站列表 item DTO 与还原/彻底删除参数语义；spec 实际设计了幻影字段和幻影写操作参数。
- **影响**：按 `docs/115-api-docs.md` 直接实现时，Infrastructure 层无法可靠映射 `CloudDriveRecycleBinItemDto`，前端 `GET /api/recycle` 可能拿不到可展示项。
- **建议**：在补采集 `/rb` 成功响应 item schema 前，将 item 字段标为 `未采集`，或将 `GET /api/recycle` 降级为只能返回顶层统计/空列表并带明确 ProblemDetails；删除 `rb/*` / `tid` 具体写接口暗示。

### H-02 文件列表与搜索分页硬上限仍是“推断值”但被设计成硬拦截

- **优先级**：🟠 中高
- **状态**：`[新]`（历史上仅标注来源，本轮发现仍作为硬规则执行）
- **specs 位置**：
  - `requirements.md:31`：说明 `limit=1150`、`offset+limit≤10000` 源自开放平台文档推断
  - `requirements.md:110,116`：`/files` 对 `limit > 1150` 返回 HTTP 400
  - `requirements.md:126,128`：`/files/search` 对 `offset + limit > 10000` 返回 HTTP 400
  - `design.md:829,845`：Input DTO 注释继续固化最大值
  - `frontend/requirements.md:155`：前端也预期 `offset+limit` 超限会返回 400
- **官方依据**：`docs/115-api-docs.md:48-128`、`docs/115-api-docs.md:386-431` 仅采集到 `offset/limit` 参数，未给出 `1150` 或 `10000` 上限。
- **差异说明**：spec 已承认这些值不是网页端文档事实，但仍把它们写成服务端硬校验，会让后端在真实 115 允许的范围内提前拒绝请求。
- **影响**：不满足用户要求“根据 `docs/115-api-docs.md` 可以直接访问 115”；实现会被开放平台推断值截断。
- **建议**：改为系统保护默认值/软限制：默认 `limit=50`，超出本系统配置上限时可限流或提示，但不得声称是 115 网页端硬上限；若要保留硬拦截，必须补充真实网页端证据。

### H-03 `fc` 文件/目录值域在前后端 spec 内部冲突

- **优先级**：🟠 中高
- **状态**：`[新]`
- **specs 位置**：
  - `requirements.md:112`：`fc→category(1=folder,0=file)`
  - `tasks.md:156`：`fc（0=文件夹, 1=文件）→ IsDirectory`
  - `design.md:1030`：文件列表 `fc` 值域写为 `0=文件夹, 1=文件`
  - `frontend/design.md:830`：前端 DTO 注释写为 `fc (1=folder, 0=file)`
- **官方依据**：`docs/115-api-docs.md:229-270` 只采集 `fc` 为 number，未给出值域；spec 自身也标注该值域来自开放平台推断。
- **差异说明**：同一个 `fc` 在 integration requirements/frontend design 中是一套语义，在 integration tasks/design 注释中是反向语义。
- **影响**：可能导致前端把文件夹当文件、把文件当文件夹，进而影响双击打开、目录导航、批量下载、上下文菜单。
- **建议**：在真实网页端样本确认前不要硬编码 `fc` 值域；短期应统一三文件为“值域未采集，需按真实响应验证”，并用 `isDirectory` 映射测试锁住最终语义。

### H-04 `passportapi.115.com` 被 requirements 排除，但 design 仍列为基础设施运行域名

- **优先级**：🟠 中高
- **状态**：`[新]`
- **specs 位置**：
  - `requirements.md:29`：明确排除 `passportapi.115.com/*`
  - `design.md:47`：声明不调用 `passportapi.115.com`
  - `design.md:459`：基础设施域名表第 7 行仍列 `passportapi.115.com`，用途为“登录态探测（预留）”
- **官方依据**：`docs/115-api-docs.md:1934-1949` 采集的 passportapi 端点是账号安全预警；登录态探测在当前 spec 已由 `GET webapi.115.com/files?cid=0&limit=1` 承担。
- **差异说明**：design 同时声明“不调用 passportapi”与“预留 passportapi 登录态探测”，形成反向追溯冲突。
- **影响**：实现者可能误加 passportapi Named HttpClient 或探测逻辑，偏离已定的 Cookie + webapi 方案。
- **建议**：删除域名表第 7 行，或移入“明确排除端点”说明；登录态探测只保留 `webapi.115.com/files?cid=0&limit=1`。

### M-01 云下载 quota 任务仍保留“等效端点”松口径

- **优先级**：🟢 低
- **状态**：`[新]`

- **官方依据**：`docs/115-api-docs.md:1187` 明确为 `GET 115.com/web/lixian/?ct=lixian&ac=get_quota_package_info`
