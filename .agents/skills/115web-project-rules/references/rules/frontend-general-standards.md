# 通用前端开发规范

## 适用范围

本规则是仓库级通用前端基线，适用于：

- 前端规格文档整理与审查
- 页面、组件、Composable、Store、Service、API 适配层设计
- 浏览器端交互、状态管理、媒体预览、测试与可访问性实现

当以下来源发生冲突时，优先级如下：

1. 当前后端实际接口契约
2. 当前项目或 feature 的 `requirements.md`、`design.md`、`tasks.md`
3. 当前项目或 feature 的专用前端规范
4. 本规则文档

---

## 核心原则

- 前端代码应保持**边界清晰、职责单一、状态显式**
- 页面层负责编排，业务逻辑不应散落在视图模板中
- 所有重要异步状态都应具备可观测的加载态、失败态，并按场景需要提供成功态与空态
- 用户可感知的交互优先于内部实现细节，避免“接口成功但用户无反馈”的实现
- 在安全性、性能、可维护性冲突时，优先保证安全性与正确性

---

## 技术栈选择原则

- 新前端模块优先使用支持类型系统和现代构建能力的主流框架
- 优先采用 `TypeScript` 提升接口契约、状态模型与组件参数的可验证性
- 请求取消优先使用 `AbortController` / `AbortSignal`
- 不再为新实现引入 `Axios CancelToken`
- 样式体系应优先支持 Design Token、主题变量与组件级封装
- 不应无理由引入与现有职责重叠的新基础设施库

---

## 分层与目录建议

推荐的职责划分如下：

- `views/`：页面装配、路由入口、页面级布局与模块编排
- `components/`：可复用 UI 单元，只处理展示逻辑与局部交互
- `composables/`：可复用交互逻辑、表单逻辑、状态派生与副作用封装
- `stores/`：跨组件共享状态、会话态、列表态、筛选态、任务态
- `services/`：业务编排、轮询、资源恢复、下载/上传调度等横切逻辑
- `api/`：HTTP 请求、参数组装、错误映射、DTO 归一化
- `types/`：共享 DTO、输入模型、结果模型、枚举与联合类型
- `utils/`：纯函数与无副作用工具逻辑

推荐数据流：

- `View -> Store/Composable -> Service -> API -> Backend`

禁止事项：

- 组件中直接散落原始网络请求
- 在多个组件或 Store 中重复声明相同 DTO
- 在视图层直接编写后端错误码和枚举兼容逻辑

---

## 路由与授权规范

- 路由应表达清晰的页面语义，而不是仅映射技术实现细节
- 未授权态、无权限态、功能禁用态都应有明确 UI 承载方式
- 浏览器 OAuth 流程优先采用 `Authorization Code + PKCE`
- OAuth 回调必须具备 CSRF 保护；可通过校验 `state`、依赖 PKCE 或 OpenID Connect `nonce` 实现
- 若产品存在登录前来源页恢复需求，应保留 return URL 或等价恢复上下文
- 不应在前端持久化不必要的敏感凭据
- 若系统采用 BFF 或服务端会话，优先由后端承接敏感 OAuth 交换责任

---

## API 适配层规范

### 通用职责

- 统一创建请求客户端实例与请求/响应拦截器
- 统一处理认证失效、取消请求、超时、网络异常与业务错误
- 已取消请求或用户主动中断请求通常不应触发全局错误提示
- API 层应输出适合前端消费的 DTO，而不是把原始后端模型直接扩散到页面层
- 后端字段兼容、错误映射、枚举归一化应收口在 API 边界

### 请求与异常处理

- 同一资源的重复请求应尽量具备去重、取消或覆盖策略
- 搜索、自动完成、无限滚动等高频请求应根据交互特征采用防抖、节流、取消或去重策略
- 对临时资源地址、签名链接、短期预览链接等可过期资源，在已知为临时链接失效的场景可考虑一次透明重试
- 自动重试次数必须可控，避免无限重试或错误风暴

## 状态管理规范

- 只有跨组件共享或跨页面存续的状态才应进入 Store
- 组件私有 UI 状态优先保留在组件本地或 Composable 中
- 同一份业务数据只能有一个主数据源，避免双写与镜像状态漂移
- 所有异步动作至少维护：`idle`、`loading`、`success`、`error` 中的必要状态
- 列表页应显式维护筛选、排序、分页、选择态和刷新态
- 重要上下文切换后，应同步清理依赖旧上下文的派生状态

---

## 数据密集型页面规范

- 大列表优先考虑分页、无限滚动或虚拟滚动策略
- 无限滚动优先使用 `IntersectionObserver` 或等价能力
- 缩略图、媒体封面、次要资源应使用懒加载
- 服务端已支持排序或筛选时，应优先使用服务端能力
- 若降级为前端本地排序或筛选，必须明确告知作用范围
- 批量操作需要明确的选择反馈、进度反馈与结果反馈

---

## 预览、媒体与临时资源规范

- 列表中的预览应优先使用缩略图或专门的轻量资源，而不是完整原始资源
- 图片、视频、文档等预览界面必须具备加载态、失败态与恢复入口
- 如果使用 `PDF.js`，必须显式配置 worker 资源
- 如果使用 HLS 播放，优先复用浏览器原生能力或成熟播放器封装
- 对脚本型、矢量型或存在潜在注入风险的资源类型，应显式定义安全边界

---

## 交互、可访问性与响应式规范

- 危险操作必须有确认机制，且文案应明确结果与不可逆后果
- 模态、抽屉、弹层打开后，应管理焦点范围与快捷键作用域
- 文本输入、可编辑控件或交互控件获得焦点时，应暂停全局快捷键
- 文本与图形界面元素应满足基本可访问性对比度要求，目标为 `WCAG AA`；普通文本至少 `4.5:1`，大文本至少 `3:1`，图标和关键 UI 组件状态建议不低于 `3:1`
- 非必要动画应尊重 `prefers-reduced-motion`
- 响应式断点应在项目内保持一致，并在项目级规范中明确写出
- 移动端可按场景将右键菜单退化为长按菜单或底部动作面板
- 离线、只读、限权等全局环境状态应有稳定可见的反馈

---

## 测试规范

- 中大型交互前端优先覆盖单元测试、组件测试与端到端测试三层验证；简单展示型页面可按风险裁剪
- 对稳定不变量可补充属性测试或等价随机测试
- 优先覆盖：
  - 状态流转
  - 错误态与恢复路径
  - 加载态与空态
  - 导航与上下文恢复
  - 请求取消、去重与重试
  - 授权边界与权限退化
- 测试应关注可观察行为，而不是绑定具体实现细节
- 组件测试优先在边界处 mock 网络，不直接穿透到真实外部服务

---

## 禁止事项

- 不在组件中散落原始 `Axios` 调用
- 不把后端原始响应结构直接作为所有页面的长期内部模型
- 不把临时兼容逻辑扩散到多个页面或组件重复实现
- 不吞掉异常后只在控制台输出而不给用户反馈
- 不在未定义快捷键作用域时注册全局键盘行为
- 不在没有加载态、错误态和空态设计的前提下交付数据密集型页面

---

## 维护说明

- 本文档只保留通用前端规则，不承载单个业务模块的接口契约
- 具体业务模块应在 `.windsurf/rules` 下补充项目级前端规范
- 若某条规则仅适用于单个业务模块，应迁移到对应项目级规范，而不是继续留在本文档中
